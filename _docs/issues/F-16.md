## Goal

`.gitignore` ignores only `dev.db`. The backend suite writes `backend/test.db` (and AC blocks write
`_b15ac.db`-style scratch files), and `merge.sh` runs the suite in the main checkout, so the next
merge refuses with "main checkout is dirty" because of a leftover test database. Ignore the pytest
artifacts repo-side.

## Context

The Orchestrator handover records this as a repo-side fix rather than a per-merge workaround:

  `merge.sh` runs its suite in the MAIN checkout, so test artifacts there make the NEXT merge refuse
  with "main checkout is dirty". `backend/test.db` and `*.db` are in the scratch clone's
  `.git/info/exclude`; `.gitignore` covers only `dev.db` (a later docs issue should fix that
  repo-side, not per-issue).

Doing it in `.git/info/exclude` is invisible to every other clone and to CI, so it does not fix the
class of failure. This issue fixes the tracked `.gitignore`.

Measured today against this checkout: `grep -n 'db' .gitignore` returns `4:dev.db` only, and
`git check-ignore -q backend/test.db` exits non-zero (not ignored).
