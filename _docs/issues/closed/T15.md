## Goal

When this is done: `frontend/src/api/mock` is reachable from the app ONLY via a dynamic import behind an `import.meta.env.DEV` guard — no production build can link the mock layer, whatever `VITE_USE_MOCK` says — and the production build mechanically asserts (and fails on) an emitted bundle that contains the mock-request-handler marker, a `1234` PIN literal, or a mock-jwt-token string; the mock's seed PIN is read from env, with no hardcoded `1234` literal left in the mock/seed source.

### AC-1 — the mock module is reachable only via an import.meta.env.DEV-guarded dynamic import: no static import anywhere in the production path, and every importing file carries the DEV guard

```bash
root=$(git rev-parse --show-toplevel 2>/dev/null) || root=.
cd "$root" || exit 1
[ -d frontend/src ] || { echo "FAIL AC-1: not run from the repo root (frontend/src missing)"; exit 1; }

q="'"
# Every quoted module specifier that names the mock module ('./mock', '@/api/mock',
# '.../mock/seed', ...) from OUTSIDE the mock module itself (mock importing its own
# seed is fine - the whole module is what must stay out of the production bundle).
all_hits=$(grep -rnE "[${q}\"][^${q}\"]*/?mock(/[^${q}\"]*)?[${q}\"]" \
  frontend/src --include='*.ts' --include='*.tsx' | grep -v '^frontend/src/api/mock/' || true)

[ -n "$all_hits" ] || { echo "FAIL AC-1: nothing outside frontend/src/api/mock references the mock module - the dev mock layer is unreachable (the contract is a DEV-guarded dynamic import, not a deletion)"; exit 1; }

# Arm 1: no STATIC import of the mock module outside the mock directory - a static import
# can be linked into the production bundle.
static_hits=$(printf '%s\n' "$all_hits" | grep -E "from[[:space:]]*[${q}\"]" || true)
if [ -n "$static_hits" ]; then
  printf '%s\n' "$static_hits"
  echo "FAIL AC-1: static import of the mock module outside frontend/src/api/mock - the production build can link it"
  exit 1
fi

# Arm 2: every file that imports the mock module (necessarily dynamic) carries an
# import.meta.env.DEV guard - the guard a production build constant-folds away (the
# VITE_USE_MOCK flag alone is an env value, not a build-mode invariant).
while IFS= read -r hit; do
  [ -n "$hit" ] || continue
  f=${hit%%:*}
  if ! grep -q "import\.meta\.env\.DEV" "$f"; then
    printf '%s\n' "$hit"
    echo "FAIL AC-1: $f imports the mock module without an import.meta.env.DEV guard (a VITE_USE_MOCK env flip links it into the production build)"
    exit 1
  fi
done < <(printf '%s\n' "$all_hits")
echo "PASS AC-1: frontend/src/api/mock is reachable only via an import.meta.env.DEV-guarded dynamic import - no production build can statically link it"
```

`# RED at 9f514e9:` arm 2 fails — the only import of the mock module is `frontend/src/api/client.ts:16` (`await import('./mock')` inside `mockRequest`), and `client.ts` gates the call on `import.meta.env.VITE_USE_MOCK === 'true'` (`client.ts:32`) — an env flag, not a build-mode guard; the file contains no `import.meta.env.DEV`. Arms 0/1 pass at HEAD (the import is already dynamic and no static import exists).

### AC-2 — the production build under the adversarial VITE_USE_MOCK=true flip emits NO mock-request-handler marker, NO 1234 PIN literal, and NO mock-jwt-token string in dist/ (the assertion is the enforced invariant; a dirty build must fail)

```bash
root=$(git rev-parse --show-toplevel 2>/dev/null) || root=.
cd "$root" || exit 1
[ -f frontend/package.json ] || { echo "FAIL AC-2: not run from the repo root (frontend/package.json missing)"; exit 1; }
NODE22=/mnt/c/Users/tw097/Desktop/261003_ai_test/.cache-node22/node-v22.23.3-linux-x64/bin
[ -x "$NODE22/node" ] || { echo "FAIL AC-2: node22 binary missing at $NODE22/node - WSL Node 18 ESM is broken, the node22 cache is required"; exit 1; }
export PATH="$NODE22:$PATH"
cd frontend || exit 1
rm -rf dist
# Production build under the AUDIT'S adversarial flip (VITE_USE_MOCK=true - the env flip
# that makes the mock layer reachable at HEAD, and that a .env or deploy env can still
# attempt after the fix): the invariant is that NO production build links the mock layer,
# whatever the flag says. Real env vars override any .env file, so the flip is authoritative.
if ! VITE_USE_MOCK=true timeout 280 npm run build > /tmp/t15-ac2-$$.log 2>&1; then
  tail -n 40 /tmp/t15-ac2-$$.log
  rm -rf dist; rm -f /tmp/t15-ac2-$$.log
  echo "FAIL AC-2: production build (vite build, node22) failed - see log above"
  exit 1
fi
rm -f /tmp/t15-ac2-$$.log
[ -d dist ] || { echo "FAIL AC-2: build reported success but dist/ was not emitted"; exit 1; }
trap 'rm -rf dist' EXIT

# Arm 1: no mock-request-handler marker in the emitted bundle (the I-01 convention: a built
# asset containing the marker means the mock layer is still reachable).
if grep -rn "mock-request-handler" dist/ > /dev/null 2>&1; then
  grep -rn "mock-request-handler" dist/ | cut -c1-160 | head -n 5
  echo "FAIL AC-2: emitted production bundle contains the mock-request-handler marker - the mock layer is still reachable"
  exit 1
fi
# Arm 2: no 1234 PIN literal in the emitted bundle. Quoted form on purpose: a bare 1234
# substring also occurs in a dependency's base32 charset constant ("0123456789...") and
# would false-positive; esbuild emits string literals double-quoted, so "1234" is the PIN.
if grep -rn '"1234"' dist/ > /dev/null 2>&1; then
  grep -rn '"1234"' dist/ | cut -c1-160 | head -n 5
  echo "FAIL AC-2: emitted production bundle contains the 1234 PIN literal - the seed PIN is still hardcoded in shipped code"
  exit 1
fi
# Arm 3: no mock-jwt-token string in the emitted bundle (the static mock bearer).
if grep -rn "mock-jwt-token" dist/ > /dev/null 2>&1; then
  grep -rn "mock-jwt-token" dist/ | cut -c1-160 | head -n 5
  echo "FAIL AC-2: emitted production bundle contains the mock-jwt-token string - the static mock bearer is still shipped"
  exit 1
fi
echo "PASS AC-2: production build under the VITE_USE_MOCK=true flip emits no mock-request-handler marker, no 1234 PIN literal, and no mock-jwt-token string in dist/"
```

`# RED at 9f514e9:` arms 2 and 3 fail — the flip build succeeds but emits an extra 5.69 kB chunk (`dist/assets/index-CMJfwld6.js`) containing `pin:"1234"` (from `seed.ts:38`) and `token:"mock-jwt-token-1234"` (from `mock/index.ts:82`); the quoted-`1234` grep and the `mock-jwt-token` grep both match it. Arm 1 (marker) does NOT fire at HEAD because esbuild minification strips the `// mock-request-handler` comment (the marker exists only as a comment at `client.ts:33`) — it is a canary for the post-fix state, and the PIN/JWT arms carry the RED. The plain (flag-unset) build at HEAD is already clean, which is exactly the audit's point: the exclusion depends on the build-time flag value (a comment, not an invariant) — hence the AC asserts the invariant under the flip.

### AC-3 — the seed PIN is parameterised from env even in the mock: no 1234 literal anywhere in the mock/seed source, and the mock source reads the PIN from import.meta.env (env var or build-time define)

```bash
root=$(git rev-parse --show-toplevel 2>/dev/null) || root=.
cd "$root" || exit 1
[ -d frontend/src/api/mock ] || { echo "FAIL AC-3: not run from the repo root (frontend/src/api/mock missing)"; exit 1; }

# Arm 1 (negative): no hardcoded 1234 literal anywhere in the mock/seed source - this
# covers both the seed PIN (seed.ts) and the mock bearer derived from it
# ('mock-jwt-token-1234', mock/index.ts).
if grep -rn "1234" frontend/src/api/mock/; then
  echo "FAIL AC-3: hardcoded 1234 literal in frontend/src/api/mock/ - the seed PIN (or a mock token derived from it) is still a literal"
  exit 1
fi

# Arm 2 (positive): the mock/seed source reads the PIN from env - some file under
# frontend/src/api/mock/ references BOTH 'pin' and 'import.meta.env' (a VITE_ env var or a
# build-time define read as import.meta.env.KEY).
found=$(for f in $(find frontend/src/api/mock -type f \( -name '*.ts' -o -name '*.tsx' \) | sort); do
  if grep -qi "pin" "$f" && grep -q "import\.meta\.env" "$f"; then echo "$f"; fi
done)
if [ -z "$found" ]; then
  echo "FAIL AC-3: no file under frontend/src/api/mock/ reads the seed PIN from import.meta.env - the PIN is not parameterised from env"
  exit 1
fi
echo "PASS AC-3: no 1234 literal in the mock/seed source, and the seed PIN is read from env ($found)"
```

`# RED at 9f514e9:` both arms fail — arm 1 matches `seed.ts:38` (`pin: '1234'`) and `mock/index.ts:82` (`token: 'mock-jwt-token-1234'`); arm 2 finds no file under `frontend/src/api/mock/` that references `import.meta.env` at all (the mock reads nothing from env).
