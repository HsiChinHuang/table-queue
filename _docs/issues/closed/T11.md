## Goal

When this is done: a guest's waitlist entry is protected by a server-minted opaque status credential with at least 128 bits of entropy, returned at join time, that is the only thing that authorizes cancellation; the 3-digit phone tail remains a READ-ONLY lookup factor (it authorizes the status read and nothing else, and never hands out the capability); the guest credential never rides in a URL query string (memory or hash transport); the public app declares `Referer-Policy: no-referrer`; and `_docs/specs.md` states the new credential contract instead of the derived-token / tail-cancel one.

def entropy_bits(token: str) -> int:
    if re.fullmatch(r"[0-9a-fA-F]+", token):
        return len(token) * 4
    if re.fullmatch(r"[A-Za-z0-9_\-]+", token):
        return len(token) * 6
    return len(token) * 4  # unknown alphabet: score at the conservative hex rate


def legacy_digests(row) -> list[str]:
    """The sha256 digests of the pre-fix derive_status_token formula, both created_at renderings."""
    variants = [row.created_at]
    if isinstance(row.created_at, datetime) and row.created_at.tzinfo is None:
        variants.append(row.created_at.replace(tzinfo=UTC))
    return [
        hashlib.sha256(
            f"{row.id}|{row.phone}|{created.isoformat()}".encode("utf-8")
        ).hexdigest()
        for created in variants
    ]

## Implementation notes

Orientation, not instructions: the pre-fix surface is mapped in Context; the ACs pin the observable properties, not the shape (D-2).

- **Shape chosen (D-2): persisted per-row value.** `WaitlistEntry` gains a nullable `status_token` column (`String(64)`); the schema builds via `create_all`, no migration step. `waitlist.py` replaces `derive_status_token` (sha256 over row data — gone, `hashlib` gone from the module) with `mint_status_token() = secrets.token_hex(32)`: 64 hex chars, 256 bits of entropy, opaque, non-derivable from stored columns. `join_waitlist` mints and stores it; the join response's `status_token` is the stored value and `status_url` is now the bare `/status/{queue_number}` path (no query string), so no backend-emitted URL can leak the credential.

## Decision

PM (groom round):

- **D-1 — one uniform refusal: no valid minted credential, no access.** Any request that does not carry a valid minted token is answered 404 `WAITLIST_NOT_FOUND` with no entry state change — a cancel sent with phone tail only, with a forged token, or with no credential at all, and a status read sent with no credential. This is exactly the response set `_docs/openapi.yaml` already declares (status: 200/404; cancel: 200/404/409 — at HEAD, BOTH the credential-less status read and the credential-less cancel are answered 422 `VALIDATION_ERROR`, a status neither operation declares), it keeps the B-06 convention that a bad or missing credential never confirms existence, and it closes the 1000-key-space hole with one rule instead of a per-factor menu. The 3-digit tail remains a READ-ONLY factor (D-5) and no longer authorizes any write.
- **D-2 — the capability is opaque, ≥128 bits, non-derivable, and `status_url` stops carrying it.** The join response keeps `status_token` (now a server-minted opaque value with ≥128 bits of entropy, not computable from stored columns — AC-1 measures entropy from the alphabet in use and rejects any truncation of the legacy sha256-over-row digest). Whether the capability is persisted per row (new `status_token` column) or minted statelessly (server-signed) is SW's choice. If `status_url` remains in the response, it is the bare `/status/{queue_number}` path — no token, no query string — so no backend-emitted URL can leak the credential.
- **D-3 — frontend transport: query-string absence is the pin; memory or hash are both allowed.** After join and after lookup, the browser URL's QUERY STRING carries no token and no phone tail; memory (module/store state) or hash (`#…`) transport both satisfy the AC (the hash is never sent to the server and never reaches Referer/access logs, which is why the draft licenses it). `StatusPage` must not read the credential out of `searchParams`.
- **D-4 — specs.md pins the new contract (AC-5's arms are its mechanical reading).** No `?token=` navigation documented anywhere; the token described as a server-minted opaque credential; cancellation tied to the minted token with the tail documented as a read-only factor; `status_token` stays in the join-response documentation.
- **D-5 — the last-3 factor STAYS, as a READ-ONLY lookup factor.** The draft says "if product wants it"; the PM pins "yes": the tail remains the documented recovery path for a guest who lost their token (specs.md §15), it authorizes the today-bounded status read (B-06) and nothing else, and a status response never returns the minted capability to a tail-only caller.
