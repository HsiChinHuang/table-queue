## Reason (audit provenance)

SEC AUDIT (2026-10-03, `audit-A-out/report.md` + `audit-D-out/report.md`) — HIGH, log-hygiene class:

- **A-14** — uvicorn's access log prints the full request line, so the `/status` lookup's query string (`?token=…&phone_last3=…`) lands in stdout verbatim.
- **D-3** — `echo` is decoupled from `env` and defaults off (that half is T20, merged); the remaining half is the `[SQL: …]`-inside-an-exception-message leak, which travels the **logging path** and is not an `echo=` leak — owned by T21 per T20's D-3 scope split.
- **D-4** — unhandled-exception 500s log a full traceback (SQLAlchemy frames included) to stdout, per attempt.

Specs §15 (specs.md lines 593-598) is the product-level contract: "Phone not logged." / "Name not logged." / "Token not logged." At HEAD the contract is violated end-to-end (token via the access log; name/phone via the echo path when `SQL_ECHO=true`; binding lines via the 500 path).

## Goal

When this is done: the TableQueue backend process log (stdout/stderr under **any** documented uvicorn startup — `make dev`, the README's bare command, or a plain `uvicorn app.main:app`) never carries a guest name, phone number, PIN, status/staff token, or `Authorization` value — not via SQL/parameter echo at any `SQL_ECHO` value, not via the 500 traceback path (traceback still emitted, binding lines gone), not via the access log (query strings masked on the credential-carrying `/status` lookup family) — and specs.md §15 lines 593-598 hold end-to-end.

## Implementation notes

PM-recommended fix set for the SW round (SW confirms or replaces; the ACs pin behaviour, not mechanism):

1. **One app-owned logging setup** — new `backend/app/logging_config.py` (or equivalent in `main.py`), invoked at app import **after** the engine is created (order matters: `create_engine(echo=True)` bumps `sqlalchemy.engine` to INFO, so the pin must run later to win).
2. **Pin `sqlalchemy.engine` (and siblings `sqlalchemy.pool`/`sqlalchemy.orm`) to WARNING** — statement echo never reaches the log at any `SQL_ECHO` value (AC-1, AC-2).
3. **Redaction filter on the root handler** — strips the `[SQL: …]` and `[parameters: …]` segments (tag and value) from formatted records. It must sit where **both** the app `errors.py` 500 log and uvicorn's "Exception in ASGI application" log propagate (root handler), since both were observed at the groom baseline (AC-2).
4. **Access log owned by the app, effective for any uvicorn startup** — disable the raw `uvicorn.access` logger (uvicorn 0.52.4 gates the access log on `uvicorn.access.hasHandlers()` at protocol start, so removing its handler before the first connection is enough) and emit the access line from an app-level middleware that masks the query string on the credential-carrying lookup family (`GET /api/v1/waitlist/{queue_number}`); masking all query strings is acceptable and simpler (AC-3, AC-4).
5. **500 handler stays the single app-level unhandled-exception log site** (`errors.py`, `exc_info` kept — the traceback is still emitted, redacted by 3) (AC-2).
6. **Docs** — README "Run" section + Makefile: state the log-hygiene contract (no log line carries phone/name/token/PIN/Authorization; `SQL_ECHO` never logs parameter values).
7. **Tests** per Test requirements.

## Decision

PM (groom round):

- **D-1 — behaviour over mechanism.** The ACs pin what reaches the log (observable), not how (logger config, middleware, filter class). SW chooses the mechanism within the Constraints.
- **D-2 — masking is app-level, not CLI-flag-level.** `--no-access-log`/`log_config` flags on one Makefile target are insufficient: the README's bare command, the Makefile's RUN_UVICORN, and any future flag-less startup must all be safe. uvicorn 0.52.4's `hasHandlers()` gate makes app-level ownership possible without a uvicorn upgrade.
- **D-3 — redaction removes the whole binding segment (tag and value), and the traceback stays emitted.** The 500 path remains diagnosable (frames, message, exception type); only the `[SQL: …]`/`[parameters: …]` segments are stripped. A redaction that keeps the tag with a placeholder value does not satisfy AC-2.
- **D-4 — the `SQL_ECHO` flag stays (T20's name pin) and stays default-off; its effect on the log is: parameter values are never logged at any flag value.** Whether `SQL_ECHO=true` still prints SQL text without parameters is SW's option — the AC pins the parameter-value absence only.
- **D-5 — the duplicate traceback (app handler + uvicorn ASGI) may remain if both copies are redacted; collapsing to one line is not AC-pinned.**
- **D-6 — docs carry the contract.** README/Makefile state: no log line (access, app, traceback) may carry a phone number, name, token, PIN, or Authorization value.
- **D-7 — suite count may move** (new tests land); SW records the new count in DoD; T13 (final regression gate) re-baselines the floor.
