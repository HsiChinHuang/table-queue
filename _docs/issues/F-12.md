## Goal

Build `/staff/waitlist` page with stats dashboard, search/filter, waitlist cards, and polling.

## Context

This is the core staff interface for managing the restaurant waitlist. Staff use this page to view waiting guests, call them to the table, handle no-shows, and manage the queue. See `_docs/ui.md` section 6.6 (lines 203-217) for page layout spec and section 5 for WaitlistCard component.

- Related: F-03 (API hooks), F-05 (Staff routing/layout), F-06 (Shared components)
- Design: `_docs/ui.md` sections 5, 6.6
- Plan: `_docs/plan.md` F-12

## Implementation notes

- **Files to create/edit**:
  - `frontend/src/pages/staff/WaitlistPage.tsx` - main page component
  - `frontend/src/pages/staff/WaitlistPage.test.tsx` - test file with filterByStatus tests

- **Components to use** (from F-06):
  - `WaitlistCard` - for displaying waitlist entries (`_docs/ui.md` section 5, line 384)
  - `Countdown` - for CALLED entry countdown (`_docs/ui.md` section 5, line 405)
  - `ConfirmDialog` - for destructive actions (`_docs/ui.md` section 5, line 423)
  - `StatsCard` - for dashboard metrics

- **Hooks to use** (from F-03):
  - `useWaitlist(branchId)` - fetch waitlist entries
  - `useStats(branchId)` - fetch dashboard statistics
  - `usePauseWaitlist(branchId)` - mutation for pause/resume
  - `useCloseDay(branchId)` - mutation for close day
  - `useCallEntry`, `useSeatEntry`, `useNoShowEntry`, `useRestoreEntry`, `useRevertEntry`, `useCancelEntry`, `useEditEntry` - mutations

- **Pure function design**:
  ```typescript
  export function filterByStatus(items: WaitlistEntry[], filter: 'Active' | 'Closed' | 'All'): { active: WaitlistEntry[]; closed: WaitlistEntry[] }
  ```
  - Active statuses: WAITING, CALLED, SEATED
  - Closed statuses: NO_SHOW, CANCELLED, DONE
  - Keep it trivial - just filter/split, no async

- **State management**:
  - Use Zustand `staffStore` for auth token and branch_id
  - Use TanStack Query for server state with polling

- **Polling**: Set `refetchInterval: 3000` (or `3 * 1000`) on waitlist query
