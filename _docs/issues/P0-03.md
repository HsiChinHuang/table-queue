Measured defects - these are the real substance of this issue:

- **3 of 29 schemas are never referenced.** `components/schemas/WaitlistSource`, `components/schemas/CancelledReason`, `components/schemas/WaitlistFilterStatus` each have 0 `$ref` hits. Definitions sit at `_docs/openapi.yaml:1135` (WaitlistSource), `:1139` (CancelledReason), `:1143` (WaitlistFilterStatus). The other 26 schemas are referenced at least once.
- **WaitlistEntryResponse has no `source` or `cancelled_reason` property**, although `_docs/specs.md:315` declares `source` enum `CUSTOMER | STAFF` and `_docs/specs.md:317` declares `cancelled_reason` enum nullable `CUSTOMER | STAFF | CLOSED_DAY | RESET`. `_docs/specs.md:194` and `:207` both write `cancelled_reason`. No response or request body in the whole file mentions either field name. That is why the two enums are unreferenced.
- **WaitlistFilterStatus is duplicated inline instead of referenced.** `_docs/openapi.yaml:320` declares the query parameter enum inline as `[ACTIVE, CLOSED, ALL]` with `default: ACTIVE`, while the named schema at `:1143` holds the identical list and is never used. The one other named-schema duplication is `UpdateTableStatusRequest.status`, whose inline list is `[AVAILABLE, CLEANING]` - deliberately narrower than `TableStatus` per `_docs/specs.md:262` (`OCCUPIED` cannot be set directly via `PATCH /staff/tables/{id}`), so it is not a copy of a named schema and stays inline. `ResetDataRequest.confirm` and `HealthResponse.status` (`[ok, degraded]`) duplicate nothing and also stay inline.
- **10 of 28 operations have no example at any media type.** The 28 operations need 31 media-type example blocks; only 31 `example:`/`examples:` lines exist at 14-space indent, and they are spread unevenly - 18 operations carry at least one, 10 carry none: `GET /api/v1/admin/tables`, `PATCH /api/v1/admin/settings`, `PATCH /api/v1/staff/tables/{id}`, `POST /api/v1/staff/waitlist/reorder`, `POST /api/v1/staff/waitlist/{id}/cancel`, `POST /api/v1/staff/waitlist/{id}/edit`, `POST /api/v1/staff/waitlist/{id}/no-show`, `POST /api/v1/staff/waitlist/{id}/restore`, `POST /api/v1/staff/waitlist/{id}/revert`, `POST /api/v1/waitlist/{queue_number}/cancel`. The SA draft claim "examples for every endpoint and error code" is therefore **not** true today.
- **All 7 named error responses are wired, but unevenly.** Line-level `$ref` counts: `ValidationError` 10, `Unauthorized` 20, `WaitlistNotFound` 9, `WaitlistInvalidStatus` 7, `TableNotFound` 4, `BranchNotFound` 2, `RateLimited` 2. No named response is orphaned, so AC-08 is a do-not-break invariant rather than a fix. The 20 `Unauthorized` references cover all 18 staff/admin operations (2 operations sit on a path item whose other method shares the reference line pattern), and the 7 operations carrying `security: []` - both public reads, join, status, cancel, login, change-pin, `GET /health` - are exactly the ones that must not require a bearer token.
- **Error-response breadth is thin on 17 operations**, but every operation except one declares at least one 4xx: 27 of 28 do. `GET /health` is the sole exception, declaring `200` and `503` only (`_docs/openapi.yaml:986`). The thin cases are the ones that declare only `401` or only `404` where the specs imply more (for example the 5 waitlist mutations declare nothing beyond `401`, and `_docs/specs.md` section 11 gives them `WAITLIST_INVALID_STATUS` 409 and `CONFLICT` 409).
- **No dangling error code, and no missing one.** All 13 codes of `_docs/specs.md` section 11 appear as a `code:` value in `_docs/openapi.yaml`, and every `code:` value used is one of those 13. **This corrects a claim in an earlier working draft** that `TABLE_NOT_AVAILABLE` at `_docs/openapi.yaml:447` was a dangling code: it is specified, at `_docs/specs.md:457` as `TABLE_NOT_AVAILABLE  409  Table not available`. Do not "fix" it by deleting it.

## Implementation notes

Suggested edits, in this order - all inside `_docs/openapi.yaml` only:

1. `WaitlistEntryResponse` - add `source` and nullable `cancelled_reason` as `$ref`s to the existing `WaitlistSource` and `CancelledReason` schemas. This single edit clears AC-15 for two of the three orphan schemas. Mirror the field order and nullability of `_docs/specs.md:315` and `:317`; keep the existing `example:` values valid against the extended schema (an added non-nullable field invalidates every example that lacks it - make `cancelled_reason` nullable and the existing examples survive).
2. The `status` query parameter on `GET /api/v1/staff/waitlist` (`_docs/openapi.yaml:320`) - replace the inline `enum: [ACTIVE, CLOSED, ALL]` with `schema: { $ref: '#/components/schemas/WaitlistFilterStatus' }` and keep `default: ACTIVE` by moving the default onto the parameter, since OpenAPI 3.0.3 ignores a default nested inside a `$ref`ed schema. Re-run T-20 after this: `default` placement is the one edit in this list most likely to trip the validator.
3. Add the missing media-type example to the 10 operations listed in Context (AC-10). Reuse values from the sibling operations that already have examples so AC-12 keeps passing; do not invent new seed values.
4. If T-21 is closed by adding a 4xx rather than by recording a decision, prefer `components.responses` references over inline blocks, matching the file's existing style.
5. Leave everything else alone. Do not reorder keys, do not reflow, do not convert CRLF to LF, do not re-wrap comments.
