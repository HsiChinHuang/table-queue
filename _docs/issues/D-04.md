## Context

An AC block is only worth running if it can fail. Measured on 2026-09-11, three groomed ACs could not
fail, and only one of them was found by a human:

1. `F-16` AC-4 used `git check-ignore -q "$f"` over `git ls-files`. `git check-ignore` skips tracked
   paths unless `--no-index` is passed, so the guard could never fire. Independently reproduced: a
   throwaway worktree at `5d70ea0` with `tracked_probe.db` committed via `git add -f` still printed
   `PASS AC-4`, while `git check-ignore -q --no-index` and `git ls-files -i -c --exclude-standard` both
   named the file. Recorded as the QA finding on Platform #48.
2. `P0-08` AC-1 contains no `PASS` token at all: it `echo "FAIL ..."`s on two conditions and otherwise
   prints measurements. `runacs.py` has graded it `silent` ever since it was groomed, which the gate
   tooling treats as not-green. It is harmless today only because a human read it.
3. `B-05` AC-15 piped `pytest -q 2>&1 | tail -2` and `ruff check . | tail -1` without capturing `$?`,
   deriving its verdict solely from `grep -c` of test-function names. It printed `PASS AC-15` while the
   tree had 22 collection errors and 1 ruff error. Repaired in `6f6ef24`.

The class is systematic, not incidental: writing a checker into a bash block feels like a gate, but if
the block never inspects the checker's exit status or prints an unconditional `PASS`, the AC is
decoration. Repair after repair this session came from the same three patterns.

## Goal

Make falsifiability an explicit, checkable property of an AC block in `_docs/testing.md`, and repair the
vacuous ACs that are still reachable (the one in the open issue set and the two in closed files whose
text lives in the repo and is cited by later work).

## Scope

- `_docs/testing.md`: add a falsifiability subsection.
- `_docs/issues/F-16.md` AC-4: add `--no-index` (or assert `git ls-files -i -c --exclude-standard` is empty).
- `_docs/issues/P0-08.md` AC-1: make it emit an explicit `PASS`/`FAIL` verdict.
- No product code changes. No new tooling inside the repo (the orchestrator's own gate scripts live
  outside the repository and are not part of its contract).

## Out of scope

- Rewriting any other issue's ACs. Where the same pattern appears harmlessly (a `tail` used purely for
  display, a `head` inside a `$(...)` measurement feeding a real conditional), leave it alone; the
  detector work is separate and lives in the orchestrator's tooling, not in this repo.
- Reopening F-16 or P0-08. Only their AC text changes; both stay closed.
- Changing `_docs/specs.md`.

## Behaviour

A section of `_docs/testing.md` states that an AC block must be falsifiable and names the three
anti-patterns with the correct alternative for each. Existing sections keep their numbering and meaning.

## Implementation notes

- `_docs/testing.md` is owned by PM + both (see `CONTRIBUTING.md` File Ownership); this issue is the
  docs-issue authorisation required by `AGENTS.md` rule 10 for a spec-adjacent file.
- Keep the addition in the file's existing voice and heading depth. Do not renumber existing sections.
- Do not tick or untick AC checkboxes in any issue file; AC text changes only. The project convention is
  that merged issues keep unchecked boxes and the verdict lives in the `## QA VERDICT` comment.

## Test requirements

The ACs below are the test. No pytest or npm tests apply: the deliverable is two Markdown files.

- [ ] **AC-1** `_docs/testing.md` states a falsifiability rule for AC blocks and names all three measured anti-patterns with their correct alternatives

```bash
test -f _docs/testing.md || { echo "FAIL AC-1: _docs/testing.md not found"; exit 0; }
MISSING=""
grep -qiE 'falsif|can fail|must be able to fail' _docs/testing.md || MISSING="${MISSING}falsifiability-rule "
grep -qF -- '--no-index' _docs/testing.md || MISSING="${MISSING}check-ignore-no-index "
grep -qE '\$\{?PIPESTATUS\[0\]\}?\[[:space:]]*\|\|\[[:space:]]*\$\{?[A-Za-z_]*RC' _docs/testing.md || MISSING="${MISSING}exit-status-capture "
grep -qE 'exit status|\$[?]' _docs/testing.md || MISSING="${MISSING}exit-status-wording "
if [ -z "$MISSING" ]; then echo "PASS AC-1: falsifiability rule and all three anti-pattern remedies are documented"; else echo "FAIL AC-1: missing ${MISSING}"; fi
```
