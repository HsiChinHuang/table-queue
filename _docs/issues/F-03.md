## Goal

Create centralized API client and mock layer for frontend that provides a consistent interface for all backend endpoints with mock data support for development and testing.

## Context

F-03 builds on F-02 which bootstraps the Vite frontend. This issue creates the API layer that SW will use to implement all frontend features. The API client abstracts HTTP calls, error handling, authentication, and mock switching.

Related: F-02 (Vite bootstrap), F-04 (Public pages), F-05 (Staff pages)
Design: `_docs/ui.md` (UI patterns), `_docs/openapi.yaml` (API contract)
Plan: `_docs/plan.md` F-03 section

The API client must implement 8 core behaviors:
1. Base URL from `VITE_API_BASE_URL` env var (fallback `/api/v1`)
2. Authorization header from `staffStore.token` Zustand store
3. 30s timeout with `AbortController`
4. 204 returns `null`
5. 401 → clear token, clear query cache, redirect to `/staff/login`
6. 429 → toast "Too many requests. Please try again."
7. 5xx → toast "Something went wrong. Please try again."
8. Network error → `NETWORK_ERROR` code

Error codes to map (13 from specs.md section 11 + 1 frontend-only):
`VALIDATION_ERROR`, `WAITLIST_DUPLICATE_PHONE`, `WAITLIST_NOT_FOUND`, `WAITLIST_INVALID_STATUS`, `WAITLIST_CLOSED`, `AUTH_INVALID_PIN`, `AUTH_TOKEN_EXPIRED`, `TABLE_NOT_FOUND`, `TABLE_NOT_AVAILABLE`, `CONFLICT`, `RATE_LIMITED`, `INTERNAL_ERROR`, `BRANCH_NOT_FOUND`, `NETWORK_ERROR`

- `frontend/src/api/mock/index.ts` - mock request/response handlers

- `frontend/src/api/admin.ts` - admin endpoints (tables, settings, reset)
- `frontend/src/api/public.ts` - public board/branch endpoints

- Use `fetch` with AbortController for 30s timeout

- Seed data must include: Sunny Bistro, Taipei Xinyi branch, tables A1-C2, 9 waitlist entries
