## Goal

Serve the three staff table operations from the contract - list active tables with the live party on
each occupied table, move a table between `AVAILABLE` and `CLEANING`, and release an occupied table -
so that releasing a table flips the table to `AVAILABLE` and its `SEATED` entry to `DONE` with
`closed_at` in one transaction, and so every rejection answers with the `error.code` the contract
names.

## Context

B-02/B-03/B-04 are merged, so this issue writes against existing infrastructure rather than rebuilding
it:

- `backend/app/models.py` (B-02) owns `Table` (`id` UUID, `label`, `capacity`, `section`,
  `sort_order`, `status`, `is_active`) and `WaitlistEntry` (`status`, `table_id`, `seated_at`,
  `closed_at`). Neither column list changes here.
- `backend/app/schemas.py` (B-03) owns `UpdateTableStatusRequest` (`status:
  Literal["AVAILABLE", "CLEANING"]`, i.e. the openapi enum already encoded as a type),
  `TableResponse` (`id`, `label`, `capacity`, `status`, `is_active`, `section`, `sort_order`,
  `current_waitlist`) and `TableListResponse` (`items`, `total`). The route layer imports these and
  defines none of its own.
- `backend/app/errors.py` (B-04) provides `AppError(code)` plus the registered handlers that render
  `{"error": {"code", "message", "details"}}`, map `RequestValidationError` to 422 `VALIDATION_ERROR`
  and read the code table out of `_docs/specs.md` section 11. Raise `AppError`; never hand-build an
  error envelope.
- `backend/app/dependencies.py` (B-04) provides `Staff = Annotated[dict, Depends(get_current_staff)]`,
  which validates the B-05 HS256 JWT (`sub="staff"`, `role`, `iat`, `exp`) and answers
  401 `AUTH_TOKEN_EXPIRED` for a missing, non-bearer, forged or expired token.
- `backend/app/main.py` (B-04/B-05) mounts `/health` and the auth router, and owns the one process
  `Limiter` plus `SlowAPIMiddleware`. This issue also registers `staff.router`.

Contract rulings taken before implementation, each one measured rather than assumed:

- **R-B08-1 (the owner stub's "PATCH rejects `OCCUPIED`" bullet is the body-enum case; AC-6 claims no
  status beyond the contract).** Measured on this tree, not argued: `_docs/openapi.yaml` lines 793-831
  (`PATCH /api/v1/staff/tables/{id}`) declare `200` (`description: Table updated`), `404`
  `TableNotFound` and `422` `ValidationError`, and a `grep -c 409` over that range returns 0. `_docs/specs.md`
  line 449 (section 11 table) pins `VALIDATION_ERROR` to 422 and to nothing else, and `_docs/specs.md`
  line 262 says only "`OCCUPIED` cannot be set directly via `PATCH /staff/tables/{id}`" - a sentence
  about *setting* `OCCUPIED`, with no status named and no statement at all about PATCHing an
  already-`OCCUPIED` row to a legal status. `_docs/api-examples.md` agrees ("Invalid table status PATCH
  ... 422 VALIDATION_ERROR"). Reading the owner stub's bullet against those three, the natural reading
  is the enum case, which openapi's body enum plus 422 already covers exactly. An earlier draft of this
  file ruled the same bullet to mean 409 `VALIDATION_ERROR` on an already-`OCCUPIED` row; that status is
  **not** supported by any of the three contract files, and asserting it would have made AC-6 green only
  for an implementation that invents an undeclared response (the green-UNREACHABLE class, B-05 R-B05-9 /
  B-06 AC-15 precedents). So AC-6 now pins exactly two contract-backed things - the 422 body rejection
  (a) and the 200 control call that proves the endpoint really writes (b) - and states in prose that
  PATCHing an `OCCUPIED` row to a legal status is contract-silent and therefore unclaimed here (c). The
  stub divergence stays visible in this bullet rather than being papered over; whether such a PATCH is
  200, 409 or 422 is a question for B-07's seat flow and a D-series docs repair (#42 D-02 and later),
  and no `_docs` file changes in this issue. AC-12 keeps `VALIDATION_ERROR` in the raised set via the
  malformed-path-id 422, so nothing in the error surface depends on this ruling.
- **R-B08-2 (release of a non-`OCCUPIED` table is 409 `TABLE_NOT_AVAILABLE`, contract-pure).** Here
  the stub, `_docs/openapi.yaml` (409 "Table not occupied", example `TABLE_NOT_AVAILABLE`) and
  `_docs/api-examples.md` (release an `AVAILABLE` table -> 409 `TABLE_NOT_AVAILABLE`) all agree, and
  the code is `TABLE_NOT_AVAILABLE` rather than the generic `WAITLIST_INVALID_STATUS` the waitlist
  transitions use. AC-8 pins it.
- **R-B08-3 (release is a no-op on the entry when no `SEATED` entry points at the table).** Neither
  specs 4.8 nor openapi says what happens when an `OCCUPIED` table has no `SEATED` entry - B-07's seat
  flow is what creates that pairing, and B-08 must be implementable before B-07 exists, so a released
  `OCCUPIED` table with no entry cannot be an error. AC-9 pins the only observable shape: 200 with the
  table `AVAILABLE`, and nothing else in the waitlist table touched.
- **R-B08-4 (`elapsed_minutes` is backend-computed from `seated_at`, with no clock seam).** specs
  section 13 says "Frontend does not compute time differences" and openapi types it `integer`, so the
  value comes from the backend. The frozen-clock assertion works without a clock seam: B-04's
  `get_now()` reads `datetime.now(UTC)` and `freezegun` patches that process-wide, so a probe seeds
  `seated_at = 2026-09-10T12:40:00Z`, freezes 2026-09-10T13:00:00Z and requires 20. The measured
  trap: SQLAlchemy's `DateTime(timezone=True)` stores a **naive** datetime on SQLite (measured:
  `repr(seated_at)` after a commit + expire is `datetime.datetime(2026, 9, 10, 12, 40)`), so
  subtracting the aware `get_now()` from the naive column value raises `TypeError` and the request
  becomes 500 `INTERNAL_ERROR`. `current_waitlist.seated_at` is therefore pinned as RFC 3339 UTC
  (`+00:00` offset) and AC-2 fails on the 500 rather than on a format argument.
- **R-B08-5 (`details.reason` disambiguates the two release 404s).** `_docs/specs.md` section 11 gives
  `TABLE_NOT_FOUND` one meaning ("Table not found"), and `AppError.to_payload()` includes `details`
  when non-empty while B-06's probes read it as a plain dict. A release whose id resolves to a table
  that is not `OCCUPIED` must not answer 404 at all (AC-7 seeds such a table and requires 409), so the
  404 branch can only be "no such table" or "no such active table"; the reason field distinguishes
  them without inventing an error code. The key is pinned rather than free-form so the AC can tell a
  real disambiguation from an arbitrary dict.
- **R-B08-6 (no limiter claims here).** `_docs/specs.md` section 15 limits "login, join, lookup"; the
  staff table operations are in none of those three, `_docs/openapi.yaml` declares no 429 for them,
  and B-06 AC-14 owns limiter identity. The measured posture of main is: `app.state.limiter` exists,
  `SlowAPIMiddleware` is installed, and the staff surface registers **no** decorator, so AC-11 asserts
  only that identity - presence of the shared limiter and absence of a per-router `Limiter(...)` - and
  says in its pass clause that it pins no request count.
