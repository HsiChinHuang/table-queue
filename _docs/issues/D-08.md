## Goal

`_docs/process.md`'s Lifecycle step 5 no longer sends every QA FAIL to step 3: it branches on the
issue's `Type`, so a docs-type FAIL re-runs the PM on the AC file and a code-type FAIL still goes to
the SW; a second consecutive docs-type FAIL on the same issue sets `blocked` and raises an owner
question instead of looping a third time; and nobody edits an issue's AC file while its QA gate is in
flight except the PM acting on that docs-type FAIL. Steps 1-4, step 6 and the Slot rules keep their
current bytes.

## Context

Step 5 today reads `- 5. FAIL: goto 3 (max 100). PASS: release slot, enqueue for merge.`, one clause
for every issue type. For `Type: docs` the deliverable *is* AC text inside `_docs/issues/<ID>.md`, and
`_docs/rules.md` `## Role boundaries (hard)` says `PM: edit issues/<ID>.md, groom AC. NEVER code,
NEVER test.` and `SW: write code, push branch. NEVER edit AC, NEVER close issues.` So on a docs-issue
FAIL the dispatched role cannot legally make the change, and the section's own fallback
(`When a role fails: re-run the SAME role. Never substitute.`) points at the PM while step 5 points at
the SW.

That deadlock was worked around three times by improvisation rather than by rule: D-04 round 2, B-05
round b and D-06 round b each got an ad-hoc PM re-run decided in the moment. `_docs/process.md` is
the Orchestrator's only written source for this loop, so the fix belongs there.

**What this groom specifies as the post-edit text.** The implementation phase (SW) performs the edit;
this issue's ACs grade it. The target shape is recorded here so the ACs and the implementer agree, and
every string an AC pins literally is listed in AC-6's and AC-7's blocks.

- Step 5's two existing clauses stay verbatim as the code-type branch: the line grows a
  `code-type FAIL:` prefix before `FAIL: goto 3 (max 100).` and keeps `PASS: release slot, enqueue for
  merge.` byte-for-byte.
- Two new bullet lines are added under step 5, indented two spaces so the ordered list is not
  renumbered: one routing a docs-type FAIL to the PM (re-run PM on `_docs/issues/<ID>.md`, label
  `groomed`, keep the slot, label `qa-ready` again when the re-groom is pushed, SW is never dispatched

- A new `## AC-file freeze` section (five bullets) goes between `## Lifecycle` and `## Slot rules`.
- `## Concurrency`, `## Worktrees`, `## Slot rules` and `## Env vars` are untouched; step 5 is the
  only line inside `## Lifecycle` that changes.
- The owner ruling date 2026-09-11 is recorded in the new step-5 text and in the commit message.
