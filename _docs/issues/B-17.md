## Why this exists

Found by the B-06 QA gate (Platform #32, round 3, measured by QA and reproduced by the
Orchestrator). Two independent defects, one follow-up issue because they share one root symptom:
suite-wide AC verdicts are not reproducible.

## Finding 1 - cross-module test pollution (backend)

27 of 117 tests fail when the whole backend suite runs, at BOTH B-06 commits and the base; excluding
`backend/tests/test_public_waitlist.py` and `test_public_board.py` the rest is `78 passed`. The
failing 27 are B-06's two files failing for a reason B-06 does not own.

Mechanism (isolated by QA to a two-test pair): `backend/tests/test_auth.py::use_temp_database()`
rebinds `app.database.engine` / `SessionLocal` module globals at session scope and pops
`DATABASE_URL` on teardown without restoring an externally supplied value. A later `create_all`
then lands on the `sqlite:///:memory:` engine `test_middleware.py` left behind, and the first
`seed_branch` insert dies with `No row was found when one was required`.

Reproduce:
`uv run --no-sync python -m pytest -q -p no:randomly tests/test_auth.py::test_login_rate_limit tests/test_public_waitlist.py::test_join_uses_the_injected_clock_for_the_business_date`
-> 1 failed, 1 passed; the second function alone -> 1 passed.

Fix: make the engine/SessionLocal rebinding restore the previous values (context-manager / 
fixture-finaliser symmetry), or scope the temp DB per test rather than per session. Do not weaken
B-06's public-endpoint assertions to dodge this.

## Finding 2 - suite-wide AC gates do not pin pytest ordering (docs / AC gate)

`_docs/issues/B-05.md` AC-15 runs `pytest -q` with no path argument and no `-p no:randomly`, so the
verdict of a CLOSED issue depends on which pytest plugins the machine has installed: B-05 recorded
green=16 at its merge commit `36eb081` (110 passed) and grades red=1 [AC-15] on main today (27
failed, 90 passed) purely through Finding 1 plus random ordering. B-06's AC-15 arm 3 already carries
the `-p no:randomly` pin - the same pin belongs on every suite-wide claim.

Because B-05 and B-06 are closed, this must be done as a docs issue that edits BOTH AC files under
one issue (the closure rule forbids silent post-closure edits), and the AC text must state the
restored expectations rather than a ticked box.

## Acceptance criteria (for PM to groom into executable ACs)

- Whole suite under a pinned order passes with zero failures on a clean checkout.
- The two-test reproduction above passes.
- Every AC that claims a suite-wide pytest result pins `-p no:randomly` explicitly.
- English only, no CJK; date format 2026-09-10 21:00; no ticked boxes shipped.
