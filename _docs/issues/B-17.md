## Goal

Two things are true when this is done: a whole-backend `pytest -q` run passes with zero failures
under the default (random) ordering, because no test module leaves a rebound engine, session
factory or `DATABASE_URL` behind; and every AC in the repo that claims a suite-wide pytest verdict
names its ordering pin explicitly, so a closed issue's verdict does not depend on which plugins the
machine happens to have installed.

## Implementation notes

- Suggested shape for the fix (SW owns the final choice): snapshot `database.engine`,
  `database.SessionLocal` and `os.environ.get("DATABASE_URL")` on entry and restore all three in a
  `finally` / fixture finaliser, so entry and exit are symmetric. Scope the temp DB per test if that
  is simpler - but the session-scoped autouse ordering note in `test_auth.py`'s docstring explains
  why the swap happens where it does, so a per-test scope has to preserve the rate-limit isolation
  that docstring records.
- Restoring `DATABASE_URL` means putting back the *prior* value, including "it was absent", rather
  than `pop`-ing unconditionally.
- Docs half: add `-p no:randomly` to the pytest line in `_docs/issues/B-05.md` AC-15 and confirm the
  one in `_docs/issues/B-06.md` AC-15 arm 3 stays. Both files are CLOSED issues; editing them is
  authorised by this issue's closure-rule exception (AC-5 and AC-6 are the guards that make the edit
  auditable), and the AC text must state restored expectations rather than a ticked box.
- Do not touch `backend/app/` - the measured fault is in the test fixtures.
