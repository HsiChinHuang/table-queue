## Goal

Build the `/join` page that allows guests to join the restaurant waitlist.

## Context

This page is the entry point for guests to join the waitlist. It displays restaurant/branch information and provides a form for guests to submit their waitlist request.

The page uses `usePublicBranch` hook from F-03 API layer to fetch branch information. It calls `joinWaitlist` API endpoint on form submission. The page is mounted by F-05 routing.

Design reference: `_docs/ui.md` section 6.1 (Join Page).
API reference: `_docs/openapi.yaml` POST `/api/v1/branches/{branch_id}/waitlist`.
Validation rules: `_docs/specs.md` Section 7 (Join validation).
Error codes: `_docs/specs.md` Section 11.

## Implementation notes

**Files to create**:
- `frontend/src/pages/public/JoinPage.tsx` - Main page component
- `frontend/src/pages/public/JoinPage.test.tsx` - Unit tests for `validateJoinForm`

**Key design decisions**:
- Extract form validation into a pure function `validateJoinForm` that is exported from JoinPage.tsx, making it unit-testable without network calls or mocks
- Use `react-hook-form` + zod for form handling (per frontend guidelines)
- Use `usePublicBranch` hook from F-03 API layer for branch data
- Use `joinWaitlist` API function from F-03 API layer for form submission
- Use `navigate` from react-router for navigation on success
- Display loading state using `LoadingSkeleton` variant for form
- Display error states using inline errors for form fields and toast for API errors
- Use `ConfirmDialog` for any destructive actions (not applicable here)

**Dependencies**:
- F-03: API layer (usePublicBranch, joinWaitlist)
- F-05: Routing (page mounted at /join)
- F-02: Tailwind config and theme tokens
