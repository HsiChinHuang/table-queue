## Context

`AGENTS.md` is 422 lines. Almost every section restates a file that already owns the content ("the
checkout is authoritative", "this file is the route map, not the spec"). The owner has directed that
the file end up containing exactly two sections: `## Hard rules (apply to ALL roles)` (five numbered
rules) and `## Pointers` (five bullets).

Two measured facts shape this issue:

1. **The prose is not lost by shrinking** - sections 2, 4, 6, 7, 8, 11, 13, 15 restate
   `_docs/requirements.md` sections 2/4/6/7/8/15, `_docs/specs.md` and `CONTRIBUTING.md`. But the
   verbatim text is worth keeping as a frozen archive, and one class of facts is genuinely orphaned by
   the shrink: the *pointer sentences* that tell a subagent where each fact lives. `_docs/team/sw.md`
   and `_docs/team/qa.md` never mention `_docs/requirements.md`, and the five owner-listed pointers do
   not include it - without a relocation, "all UI text in English", the state-machine summary and the
   error-code table stop being reachable by the roles that must obey them.
2. **The old text is cited by path+section 24 times** - `_docs/plan.md` (9:
   `AGENTS.md#5-project-structure`, `#7-backend-guidelines`, `#8-frontend-guidelines`), open issue
   files F-02 (#13, 4 refs), F-04 (#15, 4), F-06 (#17, 3), and README.md / CONTRIBUTING.md. Deleting
   the headings without an archive or redirect map strands 11 citations in the open issue set alone.

The five pointer targets are generic templates (`_docs/rules.md` 51L, `_docs/process.md` 43L,
`_docs/commands.md` 20L, `_docs/documents.md` 29L) that carry no TableQueue-specific content today.
`_docs/commands.md` is therefore the right home for the project command table (AGENTS.md section 6),
and `_docs/documents.md` must be updated to register any new file.

## Goal

`AGENTS.md` equals the owner-specified text. Its former content lives in: a new `_docs/project-guide.md`
(complete verbatim archive plus a content map), `_docs/commands.md` (project command table), and the
authoritative files that already own the rest. `_docs/documents.md` registers the new file and its
pre-existing broken `_docs/AGENTS.md` reference is fixed in the same commit.

## Behaviour

A subagent that reads only `AGENTS.md` gets five hard rules and five pointers; every fact formerly in
`AGENTS.md` is reachable from `_docs/project-guide.md` (archive + content map) or from the authoritative
file the old section already cited. `_docs/commands.md` answers "what do I run".

## Implementation notes

- Copy the old `AGENTS.md` with `git show HEAD:AGENTS.md` redirected into the archive section - do NOT
  retype it (retyping is how content is silently lost). Do not use `git checkout HEAD~1` after other
  commits have landed; capture the text first.
- The owner's five hard rules are the first five bullets of the old section 4 "Repo-wide rules" - keep
  the exact wording, including the backticks around `reached_state`.
- The owner's Pointers list is exactly five bullets. Do not add a sixth pointer; `_docs/requirements.md`
  reachability is delivered through `_docs/documents.md` (which is one of the five pointers).
- The archive's section headings must stay intact (same heading text, same numbering) so citations like
  `AGENTS.md#5-project-structure` can be resolved by a reader following the content map.
- Content-map row format (required by AC-3): the guide section before `BEGIN-ARCHIVE` carries a table
  with one row per old section, each naming its surviving home as a real path, each row containing the
  literal token `AGENTS.md section N` (e.g. "AGENTS.md section 6 | _docs/commands.md | make targets").
  The redirect table names F-02, F-04, F-06 and the three plan.md anchors explicitly.
- EOL is LF in this repo (`git show HEAD:AGENTS.md | head -c 40 | od -c` shows no `\r`); do not
  introduce CRLF.
- English only, including comments (AGENTS.md rule 6, surviving in requirements.md section 4).
