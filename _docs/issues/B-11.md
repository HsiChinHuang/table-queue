## Goal

Give the staff dashboard the four table-administration endpoints the contract already
declares, `GET`/`POST` on `/api/v1/admin/tables` and `PATCH`/`DELETE` on
`/api/v1/admin/tables/{id}`, so a restaurant can maintain its own table list (label,
capacity, section, ordering, active flag) without touching SQL. Today all four slots
return 404 because `backend/app/routers/` ships only `public.py`, `queue.py` and
`staff.py`; the models, schemas, error envelope and staff auth dependency the feature
needs are all already merged.

## Context

Everything below was measured on this worktree at `8d40c32` by mounting a throwaway
admin router on the real `app` object and issuing real `TestClient` requests. Product
code was not modified. Where the contract speaks it wins; where it is silent the AC
pins the shipped observable behaviour and says so.

- **R-B11-1 soft delete is an `is_active` flip.** `openapi.yaml` gives DELETE no
  response schema, `backend/app/models.py` has `is_active` on `Table`, and the AC set
  needs the row afterwards to be observable. DELETE must therefore flip `is_active` to
  false and keep the row. A hard `DELETE FROM tables` would satisfy the 204 but destroy
  the queue history the row is referenced by.
- **R-B11-2 the unique index covers inactive rows.** `models.py` declares
  `UniqueConstraint("branch_id", "label", name="uq_branch_label")` with no `is_active`
  predicate, and it is a real database index. Measured: `POST` with the label of a soft
  deleted row raises `IntegrityError` (HTTP 500 through the shipped handler), so the
  route must translate it to 409 rather than assume the label is free because the row is
  hidden. AC-5 pins this; the same index is what makes a PATCH rename onto a hidden
  label collide (AC-7).
- **R-B11-3 DELETE is 204, not `DeletionResponse`.** The contract declares
  `status_code: 204` with no content for DELETE, and the only 204 elsewhere in the
  document is an empty body. The reusable `DeletionResponse` schema exists but is
  declared by no path here, so an implementation that returns it is a contract
  violation. AC-9 asserts `response.text == ''`.
- **R-B11-4 `include_inactive` filters and `total` is `len(items)`.** Contract:
  `TableListResponse.total` is "Total tables (including inactive when requested)", i.e.
  the count of what was returned. AC-3 asserts `total == len(items)` under all three
  query forms and that the true/false sets differ by exactly the soft deleted rows.
- **R-B11-5 there is no `status` field in any admin request body.** `CreateTableRequest`
  is `label`/`capacity`/`section`/`sort_order`, `UpdateTableRequest` adds `is_active`,
  and neither sets `extra = "forbid"`, so a body carrying `status` is silently stripped.
  Measured: `PATCH` with `{"status": ...}` returned 200 and left the stored status
  untouched. AC-8 pins the field sets and the inertness, which is what keeps table state
  transitions on the B-08 staff endpoints.
- **R-B11-6 `branch_id` is not a request field.** Neither schema carries it, the
  document has no branch parameter on the admin paths, and `default_branch_id` in
  `config.py` is a single value; every admin write must therefore land on the default
  branch, never on a client-supplied one. The probe seeded branch 1 and branch 2 and
  measured that a label already used in branch 1 is accepted for branch 2 with 201, so
  the constraint really is per branch.
- **Silent, and deliberately not pinned.** These have no contract text and no single
  shipped answer, so an AC that guessed one would be a fabricated requirement. The
  implementation may choose, but must choose and document in the PR: (a) PATCH rename of
  a row onto a label that only a hidden row of the *same* branch holds (the shipped index
  says collide, the list endpoint hides the holder; AC-7 only asserts the visible-holder
  collision); (b) PATCH rename of a hidden row onto its own current label;
  (c) which `current_waitlist` rule the admin list uses, since `TableResponse` requires
  the field and the contract text names only the public `tables/{label}` route;
  (d) whether an empty-string `section` is stored as `''` or `NULL` (Pydantic accepts
  `''`, AC-10 only requires 201); (e) the value of `sort_order` when the POST omits it,
  which must merely be an integer because the column is `NOT NULL` (measured: a route
  that forwards the omitted field crashes with an `IntegrityError` 500).
