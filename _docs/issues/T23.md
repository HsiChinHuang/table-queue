## Reason (audit provenance)

SEC AUDIT HIGH (A-4 A-7 A-8, D-6): limiter reaches only /health/docs - every API route unbounded (60/30/20/40 all 200); XFF spoof bypassed the login budget 30/30; change-pin unbudgeted at 294ms bcrypt each; counters per-worker unbounded. Severity HIGH.

## Goal

When this is done: a measured burst on an `include_router`-mounted `/api/v1` route answers 429 once its budget is spent (the process-wide default limit actually reaches mounted routes), the staff change-PIN endpoint is budgeted, `X-Forwarded-For` influences rate-limit keys ONLY when a `TRUSTED_PROXIES` setting names the connecting proxy (off by default, absent from the shipped run command), and the counter store has a stated per-process cap (or shared storage) whose per-worker semantics are documented.

## Context

- **Audit provenance**: SEC AUDIT HIGH findings A-4, A-7, A-8, D-6 — all five directions below were reproduced live under WSL at 06570e6 during this groom (throwaway uvicorn server, throwaway `/tmp` SQLite store, canary PIN `583719`).
- **Environment facts at HEAD (06570e6)**:
  - `backend/app/main.py:157` — the ONE limiter: `Limiter(key_func=get_remote_address, default_limits=[GUEST_LIMIT])` with `GUEST_LIMIT = "10/minute"`, plus `SlowAPIMiddleware`; its storage is slowapi's default in-process `MemoryStorage` (frozen-clock hooks rebound onto it at import, main.py:201-220). `backend/app/services/rate_limit.py` (listed in Files) does not exist at HEAD.
  - **AC-1 root cause** (documented at `main.py` `mount()`, lines 506-523): on FastAPI 0.141.1 `include_router` appends one container that holds the sub-router; slowapi's middleware resolves handlers from the TOP-LEVEL route list only, a container answers NO MATCH, which reads as "no handler" and exempts the route from the default limit. Measured: 45/45 `GET /api/v1/public/branches/1` answered 200, while 12 `GET /health` answered 9x200 + 3x429 on the same store — `/health` is the only API surface the 10/minute default reaches.
  - **AC-2 root cause**: `app/routers/auth.py` budgets login only (`app_limiter.limit("5/minute")(login)`); change-pin is never registered — measured 25/25 wrong-PIN attempts answered 401, zero 429 (a ~294ms bcrypt check per attempt).
  - **AC-3 root cause**: uvicorn 0.52.4 defaults to `proxy_headers=True` with `forwarded_allow_ips` = env `FORWARDED_ALLOW_IPS` or `127.0.0.1`; its `ProxyHeadersMiddleware` rewrites `scope["client"]` from `X-Forwarded-For` for a trusted peer, and the limiter keys on `request.client.host`. Measured: 15 logins with a rotating XFF answered 15/15 200 (bypass), the same burst without XFF answered 5x200 + 7x429 on the 5/minute login budget. No `TRUSTED_PROXIES` setting exists anywhere (no match in `config.py`, README, Makefile); neither shipped run command (Makefile `RUN_UVICORN`, README two-terminal command) touches XFF trust — the implicit default IS "trust 127.0.0.1".
  - **AC-4/AC-5 root cause**: the storage behind the single limiter is per-worker `MemoryStorage` with no cap attribute and no shared-storage URI (`limiter._storage_uri` unset at HEAD); no per-worker/per-process counter semantics are stated anywhere (no match in README or `main.py`; the README's Known Limitations only lists "Single worker rate limit." without stating what the counters mean per worker).
- **Related**: B-05 (#31) owns the login 5/minute registration (works at HEAD); T21 (#76) owns log hygiene — the 429 `RATE_LIMITED` contract envelope is untouched by this issue.
- **Specs**: `_docs/specs.md` §15 Security and Privacy — "Rate limit on login, join, lookup."; §16 Known Limitations — "Single worker rate limit."

### AC-4 — the counter store has a stated per-process cap or shared storage (a documented bound, not unbounded per-worker growth)

```bash

    print("shared storage:", uri)

    for data in (vars(obj), vars(type(obj))):
        for k, v in data.items():
```
