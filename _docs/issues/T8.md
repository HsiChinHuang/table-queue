## Context

Related: #37 (B-11, closed), #36 (B-10, closed), #39 (B-12 - the collateral observer).
Discovered by the B-12 SW round-2 lane as a collateral red and verified by the Orchestrator at three
revisions: red at origin/main 7ebe7247e (contains NO B-12 code), red at B-12's base 94522a1, red at
B-12's tip. The lone red is B-11 AC-1:

    FAIL AC-1: undocumented admin slot (/api/v1/admin/settings:GET, /api/v1/admin/settings:PATCH, ...)

B-11's AC-1 computes `haveflat - wantflat` over every `/api/v1/admin` path the app serves, against a
list fixed when B-11 was groomed. Every admin surface merged afterwards (B-10's settings/tables, now
B-12's reset) lengthens the difference and turns it red - including routes properly declared in
`_docs/openapi.yaml` (lines 895/980/1070/1143). A growing assertion is a groom defect.
Collateral baselines measured at main: B-10 green=15 red=0; B-11 green=13 red=1.

## Acceptance criteria

1. `runacs.py _docs/issues/B-11.md --cwd .` on main reports green=14 red=0 with the sanctioned
   gate env (TZ=UTC, DATABASE_URL, JWT_SECRET, STAFF_PIN=0000, ENV unset so conftest's
   `setdefault(ENV, development)` applies) measured in a native-filesystem git worktree, not a tar
   export. Today it reports green=13 red=1.
2. The fix is decided by a PM, not by a worker: either (a) B-11's AC-1 set-difference is narrowed
   to the admin paths B-11 itself owns, or (b) the AC is corrected to derive "documented" from
   `_docs/openapi.yaml` rather than from a hardcoded literal list. The choice must be recorded in
   the issue file with the measurement that motivated it. AC text is PM-owned; a worker may not
   choose.
3. Whichever way it goes, `runacs.py _docs/issues/B-10.md` stays green=15 red=0 and
   `_docs/openapi.yaml` still passes `openapi-spec-validator`. No admin route may be removed from
   the application to make an assertion pass.
4. The fix must not be obtained by editing `_docs/openapi.yaml`.
