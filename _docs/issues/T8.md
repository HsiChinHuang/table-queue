## Context

Related: #37 (B-11, closed), #36 (B-10, closed), #39 (B-12 - the collateral observer).
Discovered by the B-12 SW round-2 lane as a collateral red and verified by the Orchestrator at three
revisions: red at origin/main 7ebe7247e (contains NO B-12 code), red at B-12's base 94522a1, red at
B-12's tip. The lone red is B-11 AC-1:

    FAIL AC-1: undocumented admin slot (/api/v1/admin/settings:GET, /api/v1/admin/settings:PATCH, ...)

B-11's AC-1 computes `haveflat - wantflat` over every `/api/v1/admin` path the app serves, against a
list fixed when B-11 was groomed. Every admin surface merged afterwards (B-10's settings/tables, now
B-12's reset) lengthens the difference and turns it red - including routes properly declared in
`_docs/openapi.yaml` (lines 895/980/1070/1143). A growing assertion is a groom defect.
Collateral baselines measured at main: B-10 green=15 red=0; B-11 green=13 red=1.

## Decision (PM, T8 round 1 - this is what AC-2 asks for)

**Option (b) chosen: B-11 AC-1 now derives "documented" from `_docs/openapi.yaml` instead of from a
hardcoded literal list.** The rewrite is in `_docs/issues/B-11.md` AC-1 (the only place the literal
lived in AC text); no product code, no test and no contract file changed to obtain it.

Why (b) and not (a). The measurement that forced the decision, taken in a native-fs git worktree at
origin/main 8883edafd (see AC-1's `Measured today:` for the before/after):

- The served admin set at main is
  `/api/v1/admin/settings:GET, /api/v1/admin/settings:PATCH, /api/v1/admin/tables:GET,`
  `/api/v1/admin/tables:POST, /api/v1/admin/tables/{id}:PATCH, /api/v1/admin/tables/{id}:DELETE`.
  `served - declared` over `_docs/openapi.yaml` is the **empty set**: every served admin slot,
  including B-12's not-yet-in-main `POST /api/v1/admin/reset`, is already declared. The red was
  never a product defect; it was an assertion whose right-hand side was frozen in time.
- Option (a) - narrowing the literal to "exactly the four `/api/v1/admin/tables*` slots B-11
  shipped" - does not remove the defect, it only shrinks the window before it returns. The moment
  any later issue adds a `GET /api/v1/admin/tables/{id}` read route, or a `PUT`, or any new verb on
  a tables path, AC-1 reddens again and a future writer has to know which literal list to extend.
  Measured: the option-(a) difference at main is non-empty already
  (`/api/v1/admin/settings:GET, /api/v1/admin/settings:PATCH`), so the rule has to be argued about
  immediately. A defensible ownership rule is writable ("extend only the literal in B-11 AC-1 when
  B-11 itself ships a new admin slot") but it is the same trap re-armed at smaller scale, and the
  issue says to say so if it is picked. It was not picked.
- The objection to (b) is that deriving from `_docs/openapi.yaml` is tautological if the document
  can drift from what the app serves. That objection is answered by an existing, already-merged,
  independent guard rather than by a new one:
  `backend/tests/test_admin_reset.py::test_no_new_endpoints` (B-12 AC-10, merged at 445e85a4e) walks
  `app.routes` recursively, normalises `{param}` segments, exempts FastAPI's own documentation
  routes by name, and asserts `served - declared == []` over **all** paths - it deliberately reads
  the route table rather than the generated document, precisely because a handler mounted with
  `include_in_schema=False` is invisible to `app.openapi()` and is still an invented endpoint. So
  the tautology risk is covered by a different mechanism in a different file, and T8 AC-4 pins that
  guard green so nobody silently weakens it.
- Cost asymmetry: (b) is a one-block AC-text edit and goes green immediately; (a) is the same edit
  plus a standing maintenance obligation on every future admin route. There is no future admin
  route scheduled (B-14 is not in the queue), which makes (a)'s ownership rule pay for nothing.

What the SW round still has to do is stated in AC-5 and the Test requirements: the B-11 pytest
mirror. There is no literal admin-slot set in `backend/tests/` today (measured: the only admin
constants in `backend/tests/test_admin_tables.py` are `TABLES = "/api/v1/admin/tables"` and
`TABLE_KEYS`, the eight `TableResponse` fields; the slot-walking test is B-10's
`test_settings_router_registers_get_and_patch_only` in `test_admin_settings.py`), so the chosen
option makes `backend/tests/test_admin_tables.py` an allowed file for exactly one added test.
