## Context

Audit provenance: SEC AUDIT LOW-but-structural (D-11) + operator theme — NO CI EXISTS at all.
lint/test are `make` targets only (see `Makefile`), there is no advisory gate and no secret-scan,
so every fix issue in this batch lands unverified. This issue builds the regression net; prefer
scheduling it EARLY so subsequent fixes ride it. See `docs/plan.md` → phase_5_audit → t27.

Repo state at groom (measured):

- `.github/` does not exist — no workflows at all.
- Backend: FastAPI/uv, dev deps (pytest, httpx, freezegun, ruff) in `backend/pyproject.toml`
  `[dependency-groups].dev`; no `requirements-dev` file; `pip-audit` absent.
- Frontend: Node 20, `frontend/eslint.config.js` flat config (t22), `npm run typecheck`
  (`tsc --noEmit`), `npm run lint`, `npm run test` (vitest), `npm run build` (vite build +
  T15 mock-leak grep over `dist/`).
- `.nvmrc` is referenced by README/Makefile but is NOT in the tree — Node 20 must be pinned
  inside the workflow via `actions/setup-node`.
- `backend/tests/conftest.py` (t25) refuses to run without `DATABASE_URL` but `setdefault`s
  `JWT_SECRET`/`STAFF_PIN`, so CI only needs to provide `DATABASE_URL` (a throwaway sqlite URL);
  CI must not hardcode any credential.
- TZ history: closed B-14 established that a green depending on host `TZ` is not a gate;
  the pytest job must run under two pinned clocks.

## Acceptance criteria

- **ac1** — `.github/workflows/ci.yml` exists, parses as YAML, triggers on `push`, and defines
  jobs covering: backend `ruff check` (lint); backend `pytest` full suite under TWO pinned TZ
  clocks (`TZ=UTC` and `TZ=Asia/Taipei`, each with a throwaway `DATABASE_URL`); frontend
  `tsc --noEmit`, `eslint .`, `vitest --run`, and the build smoke `npm run build` (which
  includes the T15 mock-leak grep). Every frontend job pins Node 20 via `actions/setup-node`
  (`node-version: 20` or `node-version-file: .nvmrc` with `.nvmrc` containing `20`).
- **ac2** — `.github/workflows/audit.yml` exists, parses as YAML, triggers on `pull_request`,
  and defines jobs running: `npm audit` in `frontend/`, `pip-audit` in `backend/`, and a
  `gitleaks` secret scan.
- **ac3** — `pip-audit` is added to the backend dev requirements (`backend/pyproject.toml`
  dev group; install allowed in CI) and its use is documented in the README dev section.
- **ac4** — The workflow files contain no secret material: no GitHub token patterns
  (`ghp_`/`gho_`/`github_pat_` + 20+ alphanumerics), no `-----BEGIN ... PRIVATE KEY-----`
  blocks, no `JWT_SECRET` or `STAFF_PIN` assignment (tests rely on conftest defaults), and no
  `api_key`/`apiKey` literal values. Measured by grep over `.github/workflows/`.
- **ac5** — After merge to `main`, both workflows run and ALL jobs pass on the latest `main`
  commit (green on the platform; lint/test failures they surface are NOT fixed in this issue).
