## Reason (audit provenance)

SEC AUDIT INFO/portability (B-10): PG URL fails at import (psycopg2 absent) - clean failure today, but docs/config still advertise the branch; connect_args timeout is sqlite-flavoured. Every write-integrity claim in the audit is SQLite-scoped BECAUSE of this. Needs an operator/product decision - filed so it is decided, not drifted. Severity low/info.

## Goal

When this is done: the repository is honest about its one supported backend. The docs and config surface carry no claim that a PostgreSQL `DATABASE_URL` will boot (the "Future PostgreSQL / no code changes needed" passage is rewritten as an explicit unsupported statement), and the code enforces the same line: any non-sqlite `DATABASE_URL` is refused at startup by a named guard in `backend/app/database.py` with a clear, actionable error that names `DATABASE_URL` and states that only SQLite is supported - instead of the current opaque `ModuleNotFoundError: No module named 'psycopg'` at import. The B-10 `connect_args` defect is retired by the same decision: because the engine is provably sqlite-only, the sqlite-flavoured `connect_args` are correct, and the binding site says so. A fresh clone cannot believe a PG promise that cannot boot.

### AC-3 — The B-10 connect_args defect is retired: sqlite-flavoured args correct by enforcement, documented at the site

```bash

cd "$root" || { echo "FAIL AC-3: cannot cd to the repo root"; exit 1; }
[ -f backend/app/database.py ] || { echo "FAIL AC-3: not run from the TableQueue repo root (backend/app/database.py missing)"; exit 1; }
[ -x backend/.venv/Scripts/python.exe ] || { echo "FAIL AC-3: not measured - backend/.venv/Scripts/python.exe is missing (create the suite venv: cd backend && uv sync)"; exit 1; }
mkdir -p backend/.scratch
out="backend/.scratch/_t24ac3.out"; rm -f "$out"
backend/.venv/Scripts/python.exe - > "$out" 2>&1 <<'PY'
import re, sys

src = open("backend/app/database.py", encoding="utf-8").read()
lines = src.splitlines()
problems = []

guard = re.search(r"def\s+([a-z_][a-z0-9_]*)\(.*\)", src)
has_guard_call = bool(re.search(r"get_backend_name\s*\(\)\s*!=\s*[\"']sqlite[\"']", src)) or bool(
    re.search(r"(ensure_sqlite|sqlite_only|_refuse_non_sqlite|check.*sqlite)", src, re.I)
    and re.search(r"make_url|get_backend_name|dialect_name", src, re.I)
)
if not has_guard_call:
    problems.append("no dialect guard found in backend/app/database.py (want a sqlite-backend check on the URL, e.g. make_url(...).get_backend_name() != 'sqlite', reachable from the module)")

ce = re.search(r"create_engine\((.*?)\)", src, re.S)
if not ce:
    problems.append("create_engine call not found in backend/app/database.py")
else:
    block = ce.group(1)
    m = re.search(r"[\"']?timeout[\"']?\s*:\s*([A-Za-z_][A-Za-z0-9_]*)", block)
    if not m:
        problems.append("connect_args no longer binds a 'timeout' key")
    elif re.match(r"^[0-9.]+$", m.group(1)):
        problems.append("the busy timeout is an inline literal %s again - it must stay a named constant (the t19 SQLITE_BUSY_TIMEOUT binding)" % m.group(1))
    else:
        name = m.group(1)
        if not re.search(r"^\s*%s\s*=\s*[0-9]" % re.escape(name), src, re.M):
            problems.append("the timeout binding name %s is not a module-level numeric constant in database.py" % name)
```
