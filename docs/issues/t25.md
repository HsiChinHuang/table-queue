## Reason (audit provenance)

SEC AUDIT MEDIUM (D-7) + operator item O-4: *-journal/-wal/-shm and .env.local/.env.production NOT ignored (gap proven at driver level); bare pytest leaves DBs; the conftest default sqlite:///./test.db is the standing root cause. Severity medium.

## Goal

When this is done: the repository's ignore rules cover every SQLite artifact the suite can produce (main file, journal, WAL and SHM sidecars) and every local dot-env spelling an operator might create (`.env.local`, `.env.*.local`), and the test surface can no longer silently write a database file inside the tree. A `pytest` run without `DATABASE_URL` is refused at conftest import with an actionable error; a full suite run with the documented env is green and leaves zero untracked files in the repo and no per-test scratch DBs behind; and the audit's `/tmp/tq_b06_pytest.db` item is closed as inert - the module-level setdefaults that point at it can never take effect while conftest guarantees `DATABASE_URL`, and a run of the affected modules provably does not create the file.

## Context

- **Audit provenance**: see the Reason section (D-7, O-4). The D-class decision the draft defers to groom is taken here: **refusal** (conftest refuses `DATABASE_URL`-less runs) over "write only under tmp". Rationale, on the measured facts:
  - The conftest default `sqlite:///./test.db` is the standing root cause named in the audit: it silently points the import-time engine at a file inside the tree, and the tracked `backend/test.db` exists in the repo only because of that default (the pipeline's floor/import-smoke commands create/restore it).
  - Refusal makes the root cause loud at the only place it can be fixed cheaply - the test surface. "Write only under tmp" would keep a silent default and merely move the file: any test that reads `DATABASE_URL` from the environment still gets whatever the environment happened to carry.
  - Refusal is strictly smaller in diff: one guard at the top of `backend/tests/conftest.py` (before the `app.main` import, alongside the existing `setdefault` block) versus rewiring the `tq_isolated` fixture's scratch path.
- **Grounding facts, measured at the groom base `2595997` (Windows + git-bash, suite venv CPython 3.12.15)**:
  - **Current ignore surface**: the root `.gitignore` ignores `.env` (line 1) and the Python/Node runtime dirs, but none of `test.db`, `*.db`, `*.db-journal`, `*.db-wal`, `*.db-shm`, `.env.local`, `.env.*.local`. Measured: `git check-ignore` reports all seven probe paths NOT-IGNORED (AC-1 baseline FAIL).
  - **The conftest default**: `backend/tests/conftest.py` line 17, `os.environ.setdefault("DATABASE_URL", "sqlite:///./test.db")`, precedes the `app.main` import (the import-order contract in the module docstring - env bootstrap before app imports - must be preserved by the refusal guard). Measured: `env -u DATABASE_URL pytest --collect-only -q` exits 0 with 349 collected - no refusal today (AC-2 baseline FAIL).
  - **The tracked DB artifact**: `backend/test.db` is a TRACKED file (`git ls-files`). This issue does NOT untrack it (see Out of scope): the pipeline's floor/import-smoke convention creates/restores it, and one test hardcodes it - `backend/tests/test_log_hygiene.py:161` probes `Path("test.db")` in the cwd (corrupts the file to force a 500, rebuilds the schema on the way out). Measured: a full-suite run with a temp `DATABASE_URL` outside the tree FAILS that test (346 passed, 1 failed) while the same run with `DATABASE_URL=sqlite:///./test.db` is green (347 passed, 2 xfailed) - the floor URL must stay `./test.db` until that test is re-pointed (follow-up).
  - **The /tmp landmine**: four test modules carry `os.environ.setdefault("DATABASE_URL", "sqlite:////tmp/tq_b06_pytest.db")` at module level (`tests/public_fixtures.py:28`, `tests/test_public_board.py:13`, `tests/test_public_waitlist.py:24`, `tests/test_rate_limit_t23.py:27`).   - **Per-test scratch**: the `tq_isolated` fixture names `tq_test_<n>.db` in the cwd (backend/) and removes it in teardown. Measured: a full green run leaves no `tq_test_*.db` behind and no new untracked files anywhere in the repo (AC-3 baseline PASS).
  - **Green baseline (measured at the groom base `2595997`)**: `cd backend && ENV=development DATABASE_URL=sqlite:///./test.db JWT_SECRET=<32+ chars> STAFF_PIN=0000 TZ=UTC .venv/Scripts/python.exe -m pytest -q -p no:randomly` -> rc 0, `347 passed, 2 xfailed, 3 warnings in 72.10s`; `cd backend && .venv/Scripts/ruff.exe check .` -> clean (rc 0). ### AC-1 — The root .gitignore covers every SQLite artifact and local dot-env spelling

```bash
root=$(git rev-parse --show-toplevel 2>/dev/null) || root=.
cd "$root" || { echo "FAIL AC-1: cannot cd to the repo root"; exit 1; }
[ -f .gitignore ] || { echo "FAIL AC-1: .gitignore is missing at the repo root"; exit 1; }
problems=""
for pat in 'backend/test.db' '*.db' '*.db-journal' '*.db-wal' '*.db-shm' '.env.local' '.env.*.local'; do
  if ! grep -qxF -- "$pat" .gitignore; then
    problems="$problems\n  .gitignore is missing the line: $pat"
  fi
done
# --no-index: consults .gitignore only. backend/test.db is still a TRACKED
# file (untracking is the documented follow-up) and index-aware check-ignore
# never reports tracked paths as ignored, which would mask an armed rule.
for p in backend/test.db backend/whatever.db backend/whatever.db-journal backend/whatever.db-wal backend/whatever.db-shm .env.local .env.production.local; do
  if ! git check-ignore -q --no-index -- "$p"; then
    problems="$problems\n  git check-ignore: $p is not ignored"
  fi
done
if [ -n "$problems" ]; then
  printf "%b\n" "$problems"
  echo "FAIL AC-1: .gitignore does not cover the DB sidecars / local dot-env files (want the lines backend/test.db, *.db, *.db-journal, *.db-wal, *.db-shm, .env.local, .env.*.local; detail above)"
  exit 1
fi
echo "PASS AC-1: .gitignore covers backend/test.db, *.db, *.db-journal, *.db-wal, *.db-shm, .env.local and .env.*.local - all seven check-ignore probes are ignored"
exit 0
```
